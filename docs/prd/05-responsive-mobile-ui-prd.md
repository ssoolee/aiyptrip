# PRD-05. 모바일 반응형 UI/UX

## 1. 배경/목표

별도 네이티브 앱 없이, 하나의 웹서비스로 모바일과 데스크톱 모두에서
동등한 핵심 경험(코스 추천 → 지도/상세 확인 → 찜)을 제공한다. 실사용
비중이 높을 것으로 예상되는 모바일 환경을 기준(모바일 퍼스트)으로
설계한다.

## 2. 사용자 스토리

- 사용자로서, 스마트폰으로 접속해도 지도와 코스 리스트를 불편함 없이
  오가며 볼 수 있어야 한다.
- 사용자로서, 이동 중 한 손으로 조작할 수 있을 만큼 버튼/탭 영역이
  충분히 커야 한다.
- 사용자로서, 데스크톱에서는 더 넓은 화면을 활용해 지도와 리스트를
  동시에 보고 싶다.

## 3. 기능/화면 요구사항 (MoSCoW)

**Must**
- 반응형 브레이크포인트: 모바일(~480px), 태블릿(481~1024px),
  데스크톱(1025px~) 3단 기준으로 레이아웃 전환
- 모바일 하단 고정 탭바: 홈(추천) / 지도 / 찜 / 내정보(또는 로그인) 4개 메뉴
- 모바일에서 지도-리스트는 탭 또는 토글 스위치로 전환(§`02-map-realtime-location-prd.md`
  §4와 연계), 데스크톱은 2단 동시 노출
- 모든 터치 타겟 최소 44x44px 확보 (찜 하트 버튼, 탭바 아이콘 등)
- 프리셋 카드(§`01-ai-course-recommendation-prd.md`)는 모바일에서
  가로 스와이프, 데스크톱에서는 그리드 노출

**Should**
- 다크모드 대응(시스템 설정 따라가기)
- 접근성: 명도 대비 WCAG AA 이상, 주요 아이콘에 대체 텍스트(aria-label)

**Could**
- PWA(홈 화면 추가, 오프라인 캐시 일부) — 2차 검토

## 3.1 디자인 기준 소스 (디자인 토큰)

컬러/타이포/여백/모션 등 위 요구사항의 구체적 값(hex 코드, px, 폰트 등)은
[`docs/agents/06-web-design-trend-agent.md`](../agents/06-web-design-trend-agent.md)가
주기적으로 조사·갱신하는 **디자인 토큰**을 기준으로 정의한다. 이
에이전트는 사용자 요청과 무관하게 분기 단위로 최신 UI/UX 트렌드를
반영해 토큰을 갱신하며, 갱신된 값은 운영자/디자이너 검토(휴먼 리뷰) 후
이 PRD와 실제 컴포넌트 스타일(Tailwind 설정 등)에 반영한다. 즉 이
PRD는 레이아웃/구조적 요구사항을 정의하고, 세부 비주얼 값은 디자인
토큰 갱신 주기에 맞춰 이어서 최신화된다.

## 4. 레이아웃 원칙

- 좌우 여백(gutter) 모바일 기준 최소 16px 확보
- 코스 카드/장소 카드는 1열(모바일) → 2열(태블릿) → 3열(데스크톱) 그리드
- 스크롤은 세로 방향만 기본, 가로 스크롤은 프리셋 카드 등 명시적으로
  의도된 영역에 한정

## 5. 비기능 요구사항

- Core Web Vitals: LCP < 2.5s, CLS < 0.1, INP < 200ms (모바일 4G 기준)
- 이미지 반응형 제공(srcset 등)으로 모바일 데이터 사용량 최소화
- 저사양 기기에서도 지도 렌더링 부담을 줄이기 위해 지도는 필요 시점
  (탭 전환 시)에만 초기화하는 지연 로딩 고려

## 6. 성공지표

- 모바일 세션 이탈률이 데스크톱 대비 +10%p 이내 (`00-overview-prd.md` KPI)
- 모바일 Lighthouse 성능 점수 ≥ 85

## 7. 오픈 이슈

- 다크모드 1차 출시 포함 여부(리소스에 따라 2차로 이월 가능)
- PWA 도입 여부 및 우선순위 재검토 시점
