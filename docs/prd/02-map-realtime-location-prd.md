# PRD-02. 지도 · 실시간 위치 기능

## 1. 배경/목표

추천된 코스는 텍스트만으로는 실행하기 어렵다. 사용자가 코스의 동선을
지도에서 한눈에 보고, 여행 당일에는 현재 위치 기준으로 다음 목적지까지
안내받을 수 있어야 한다.

## 2. 사용자 스토리

- 사용자로서, 추천받은 코스의 전체 동선을 지도에서 한눈에 보고 싶다.
- 사용자로서, 여행 중 내 현재 위치와 다음 목적지까지 거리/소요시간을
  보고 싶다.
- 사용자로서, 위치 권한을 허용하지 않아도 코스 지도는 볼 수 있어야 한다.
- 사용자로서, 지도에서 특정 스팟을 탭하면 그 장소의 상세정보로 바로
  이동하고 싶다.

## 3. 기능 요구사항 (MoSCoW)

**Must**
- 코스 상세 화면에 지도 뷰 제공, 방문 순서대로 마커(1,2,3…) 및 동선
  라인 표시
- 마커 탭 시 장소명/카테고리 미리보기 팝업 → "상세보기" 진입
  (`03-place-detail-prd.md` 연동)
- 브라우저 Geolocation API로 사용자 현재 위치 표시(권한 동의 시)
- 위치 권한 거부/미지원 시에도 코스 지도·동선은 정상 표시(현재 위치
  마커만 생략)

**Should**
- "다음 목적지까지" 카드: 현재 위치 → 다음 스팟까지 거리, 예상 소요시간,
  이동수단(대중교통/자동차/도보) 별 안내
- 외부 지도 앱(네이버맵 우선, 대안 티맵)으로 길찾기 딥링크 연결 —
  카카오는 로그인 전용이므로 카카오맵 딥링크는 제공하지 않음

**Could**
- 실시간 혼잡도 표시(데이터 제공 시)
- 코스 진행률 표시(오늘 방문 완료한 스팟 체크)

## 4. 화면/UX 요구사항

- 모바일: 지도가 화면 상단 40~50%, 하단은 스팟 리스트(스크롤 시 지도는
  고정 또는 축소) — 지도/리스트 탭 전환 토글 제공
- 데스크톱: 좌측 리스트, 우측 지도 2단 레이아웃
- 현재 위치 권한 요청은 사용자가 "길안내 시작" 등 명확한 액션을 취할
  때 요청(진입 즉시 요청 금지 — 이탈률 상승 방지)

## 5. 데이터/연동 요구사항

- 지도 SDK: 네이버 지도 Dynamic Map SDK (Naver Cloud Platform, 마커/
  폴리라인/인포윈도우)
- 경로/소요시간: 네이버 Directions 5 API(자동차) + ODsay 대중교통
  길찾기 API(대중교통), 실패 시 좌표 기반 직선거리 fallback
- `docs/agents/03-itinerary-composer-agent.md`에서 계산한 이동시간
  데이터를 그대로 표시에 재사용(중복 계산 지양)

## 6. 비기능 요구사항

- 지도 최초 로딩 ≤ 2초 (LCP 기준에 포함)
- 위치 정보는 세션 내에서만 사용, 서버에 원본 좌표 저장하지 않음
  (찜 등 필요한 최소 정보만 저장)

## 7. 성공지표

- 코스 상세 화면 방문자 중 지도 인터랙션(마커 탭/확대·축소) 비율 ≥ 50%
- "길안내 시작" 클릭률(코스 상세 대비) ≥ 15%

## 8. 오픈 이슈

- 외부 길찾기 앱 딥링크 표준(네이버맵 우선, 티맵 차순위) 최종 확정 필요
- 실시간 혼잡도 데이터 소스 확보 가능 여부 확인 필요 (없으면 1차 제외)
