# PRD-03. 업체 상세정보 (사진 · 연락처 · 영업시간 · 리뷰)

## 1. 배경/목표

코스에 포함된 각 장소(맛집/카페/관광지/숙소)에 대해 사용자가 방문
여부를 결정하는 데 필요한 정보(사진, 연락처, 영업시간, 리뷰 요약,
지도 링크)를 제공한다.

## 2. 사용자 스토리

- 사용자로서, 장소의 실제 사진을 보고 분위기를 미리 확인하고 싶다.
- 사용자로서, 바로 전화를 걸어 예약/문의하고 싶다.
- 사용자로서, 오늘 방문 가능한지(영업시간/휴무일) 바로 확인하고 싶다.
- 사용자로서, 다른 사람들의 리뷰 요약을 짧게 보고 싶다.
- 사용자로서, 반려동물 동반 가능 여부, 주차 가능 여부를 확인하고 싶다.

## 3. 기능 요구사항 (MoSCoW)

**Must**
- 사진 갤러리(최소 1장, 여러 장일 경우 스와이프/썸네일)
- 전화번호 표시 + 탭하면 `tel:` 링크로 즉시 통화 연결(모바일)
- 오늘 기준 영업 중/영업 종료/정기휴무 상태 뱃지 + 전체 영업시간 표
- 네이버맵 등 외부 지도 링크로 이동
- 주소 텍스트 표시 및 복사 기능

**Should**
- 리뷰 요약 2문장(콘텐츠 보강 에이전트 결과, `docs/agents/05-...md` 참조)
- 평점(가능한 경우)
- 반려동물 동반 가능 여부, 주차 가능 여부 아이콘 표시

**Could**
- 예약 필요 여부 안내 및 외부 예약 페이지 링크(1차는 정보 제공만, 인앱
  예약은 범위 제외 — `00-overview-prd.md` §8 참조)

## 4. 화면/UX 요구사항

- 코스 리스트의 각 스팟 카드에서 탭하면 상세 바텀시트(모바일) 또는
  사이드 패널(데스크톱)로 오픈
- 정보 우선순위(위→아래): 사진 → 이름/카테고리/찜버튼 → 영업상태 뱃지 →
  주소/전화 → 리뷰 요약 → 지도 링크
- 정보 누락 시(사진 없음 등) 플레이스홀더로 대체하고 빈 화면처럼
  보이지 않게 처리

## 5. 데이터/연동 요구사항

- 네이버 검색 API / TourAPI에서 수집한 `places_detail` 데이터 사용
  (`docs/agents/02-place-retrieval-agent.md`, `05-enrichment-...md` 참조)
- 영업시간 원본 텍스트와 파싱된 구조화 데이터를 함께 저장(파싱 실패
  시 원본 텍스트라도 노출)

## 6. 비기능 요구사항

- 사진은 지연 로딩(lazy load) 적용, 모바일 데이터 사용량 고려해 압축/
  적정 해상도 제공
- 전화번호/주소 등은 개인정보가 아닌 업체 공개정보이므로 별도 동의
  절차 불필요

## 7. 성공지표

- 상세정보 열람 후 전화 연결(tel: 클릭) 비율
- 영업상태 뱃지 정확도(사용자 신고 기반 오류율) ≤ 5%
